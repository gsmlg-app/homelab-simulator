你正在 `gsmlg-app/homelab-simulator` 仓库中工作。请实施配套的 `implementation-plan.md`；进入仓库后将其保存到 `docs/cloud-center/implementation-plan.md`，将本目标保存到 `docs/cloud-center/codex-goal.md`。用户要求的是实现，不是再次输出一份设计后停止。

## 产品目标

用户进入一间 Cloud Center（云中心）房间，走到 Cloudflare、AWS、GCP 控制台前，通过键盘、手柄或触屏主动交互，打开原生 Flutter 面板查看资源使用和费用。房间另有一个跨云费用看板。

Flame 负责房间、移动、控制台和简洁状态；Flutter 面板负责信息展示；真实采集与费用聚合在独立于客户端生命周期的服务端进行。厂商控制台是入口，不是云资源本体。第一版不把全部资源画到地图上。

- 修复云中心依赖的同 ID 场景更新、动态节点清理、门同步与角色双状态问题，不扩展为全仓重构。
- 幂等加入一间云中心、三个厂商控制台、一个费用看板及可达出口；兼容现有存档，不重置角色或删除原设备。
- 靠近仅提示；主动交互才打开。面板打开时屏蔽场景移动、放置、商店快捷键及穿透输入，关闭后恢复焦点。
- 在当前 Flutter/Flame/Bloc/Melos 结构内开发。Web 不属于支持目标；不要为此更新整个 Flutter/Flame 版本或重套项目模板。
- 在同仓库 `services/cloud_monitor/` 新增单体 Elixir/Phoenix API-only 后端及 PostgreSQL；若实际 HEAD 已有等价服务，直接复用。不要修改 Backplane 或创建微服务。
- 实现三个真实适配器：Cloudflare 费用及 Zones/Workers/R2；AWS Cost Explorer 及 EC2/EBS/S3；GCP BigQuery 账单导出及 Compute Engine/Cloud Storage/Cloud Run。运行指标与费用分别获取。
- 费用接口的服务覆盖不能受首批资源详情列表限制。未知服务费用必须保留；没有可信关联的费用不能平均分给资源。
- 实现原生总览、费用趋势/服务拆分、资源与用量、连接状态、刷新、离线缓存和应用内预算提示。
- 实现明确标注的 Demo，以及完全独立的真实数据路径。真实接入失败时绝不能自动回退成演示金额。

## 费用与同步的硬约束

金额采用十进制；API 传十进制字符串。不同币种、费用口径、账期不能直接相加。区间费用与累计值不能双计，父级费用与子级明细不能双计。完整分页成功后才原子发布快照；重复同步必须幂等，后续调整能更新历史范围。

来源已报告费用、估算标志、费用分类及预测是不同维度；本阶段不做预测。Cloudflare 的固定订阅覆盖需单独说明；AWS 单资源费用不是普通 Cost Explorer 汇总自然提供的；GCP credits 不能让基础 cost 因数组展开而重复。

将最近尝试、最近采集成功、来源更新时间、观测区间和完整性分开。未知、缺权限、导出等待、上游延迟、真实零费用必须区分。点击刷新不能令旧账单看起来已经实时更新。

面板只查询后端缓存；云采集独立调度，有界并发、重试和请求预算。首版可使用客户端 HTTP 轮询，不要求 WebSocket/SSE。Flutter 不保存云厂商密钥，后端不记录密钥。只读云资源，预算只写本应用。
